# face

BMO の顔、`bmo-face` です。ケースの画面に映すフルスクリーンのディスプレイ、顔を描いて手直しするエディター、
その両方を支えるサーバー、そしてブリーフィングの顔を読み取る `face/expression` ツールエントリーから成ります。
一つのサービスとして 127.0.0.1:3217 で `/bmo-face/` の背後に動いています。BMO からは二つのものを借りています。
一つは Web アカウントで、エディターはこれでログインし、ディスプレイもこれでサインインします。もう一つは
リスナーストリームで、すべてのブリーフィングがその感情と BMO のプレゼンスとともにこのストリームで届きます。

## 構成

| フォルダー | 内容 |
|---|---|
| `core/` | 顔のコアとなる Rust クレートです。表情ドキュメントの検査と旧形式からの移行、目のセットと話す口のセット、ジオメトリ、ブレンド、固定クロックのドライバーを持ち、テストは `tests/` に、移行対象の旧ドキュメントは `tests/fixtures/` にあります |
| `client/` | 画面を収めた独立した Bun プロジェクトです。`@nuxt/ui` 上の Nuxt ディスプレイとエディター、画面に表示するすべての文言を `i18n/locales/` にある韓国語・英語・日本語・簡体字中国語の言語パックのキーとして置いたもの、`app/console/` にあるコンソールバンドルのエントリーと `scripts/` にあるそのビルド、`vendor/` に取り込んだ bmo-ui のリリースと `patches/` にある固定パッケージへのレイヤーのパッチ、そして `tests/` のテストがあります |
| `deploy/` | デプロイが維持するユーザーユニット `bmo-face.service`、そして `system/` に、人が一度だけ配置するネイティブディスプレイヤーのシステムユニットと PAM サービスがあります |
| `displayer/` | コア上に作られたネイティブディスプレイヤーの Rust クレートです。logind 経由でパネルを取得して CPU で描画し、顔サーバーのドキュメントと音声エンジンのブリーフィングを受け取り、音を再生し、視線ソケットを持ちます。テストとそのフィクスチャーは `tests/` にあります |
| `docs/` | 正典となるドキュメントです。顔とサーバー(`face.md`)、顔の描画の元になるデザイン(`expressions.md`)、デプロイ(`deploy.md`)、開発ベンチ(`development.md`)を扱います |
| `scripts/` | 開発ベンチのコマンド(データルートのコピーとベンチ本体)と、コアの WebAssembly ビルドです |
| `server/` | コア上に作られたサーバーの Rust クレートです。表情ドキュメントの準備、エディターのセッション、サーバーのルート、パススルー、ツールエントリーを持ち、テストは `tests/` にあります |
| `src/` | 画面が `#faces` として読み込む表情ドキュメントの TypeScript 定義、`wasm/` にあるコアの WebAssembly ビルドと画面が `#core` として読み込むその型付きモジュール、そして開発用コピーのモジュールがあります |
| `tests/` | 表情ドキュメントの定義、コアの WebAssembly ビルド、開発用コピーのテストです |

ルートには、`core/`、`displayer/`、`server/` をメンバーとする Cargo ワークスペースのマニフェストとその lockfile、
`src/`、`scripts/`、`tests/` を収めるルート Bun プロジェクトのマニフェストと lockfile、`tsconfig.json`、
`testbed.toml`、`install.toml`（新しいマシンにユニットをインストールするのに必要なもの）、二つのスキーマを添えた `tool.toml`、コンソールフェイスの宣言としてマニフェストのうち顔が決める
フィールドを持つ `console-manifest.json`、`rustfmt.toml`、`korean-ledger.json`、`LICENSE`、`CLAUDE.md` があります。
`docs/PERSONAL-DATA.md` はチェック `tests/personal-data.test.ts` を指定しており、テストスイートが他のテストと
一緒に実行します。

## ドキュメント

| ドキュメント | 内容 |
|---|---|
| `docs/face.md` | ディスプレイが何をいつ表示するか、BMO が何をどの経路で送るか、画面のサインイン方法、固定クロックとドライバー、表情ドキュメントとパスの書き方およびブレンド、顔のコアとそのインターフェース、ネイティブディスプレイヤー、エディター、サーバーのルート、コンソール画面 |
| `docs/expressions.md` | アニメーションが描く BMO の顔。フレームごとに計測した内容、色、図形の描き方、目のセット、話す口のセット、アニメーションの動き、各デフォルトの顔が描くもの |
| `docs/deploy.md` | コミットが本番に反映されるまで。リリース、ユニット、生成される画面とコンソールバンドル、ツールエントリーとプロキシ、そしてネイティブディスプレイヤーのシステムユニットと一度きりのセットアップ |
| `docs/development.md` | 開発ベンチ。データルートのコピー、それに対して動かすサーバーと画面、その背後に置く BMO の開発用コンソール、ベンチ用ログインの作り方 |
| `docs/PERSONAL-DATA.md` | どのファイルにも含めてはならない個人データ、許可される値、それを防ぐパターンチェック(`tests/personal-data.test.ts`) |

## ビルドとテスト

```sh
bmo-testbed cargo build --workspace
bmo-testbed cargo test --workspace
bmo-testbed cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all --check
bun run check:types
bun test ./tests
(cd client && bun run check)
```

Cargo のコマンドは、共有ビルドディレクトリを持つ `bmo-testbed` を通して実行します。素の `cargo` では、
ワークスペースをチェックアウト自身の `target/` にゼロからコンパイルすることになります。クレートのフォーマットと
リントは個別のステップを宣言する必要がありません。変更がクレートに及ぶと testbed の Cargo ワークスペースチェックが
全メンバーに対してそれらを実行し、変更チェックが該当クレートをコンパイルします。画面は報告する前にベンチ
(`docs/development.md`)で動作を確認します。

## バージョン

バージョンはセット全体のもので、ビルド時に git タグから読み取ります。Cargo ワークスペースのパッケージと画面の
マニフェストには、動かないプレースホルダーのバージョンが記されています。
bmo-chat の `docs/conventions.md` 「Versions」にあるとおり、オーナーが宣言するリリースでのみ上がります。
契約が変わってもバージョンは動かず、デプロイはコミットで区別します。
